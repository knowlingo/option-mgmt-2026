## Reality review (planned scope vs. what's shippable)

### 1. Playwright E2E is blocked from CI — the central finding

The plan (Phase-1 exit criteria + §test-pyramid) calls for a green Playwright
E2E job. Reality:

- **`@playwright/test` is not installed** — `apps/web/package.json` has no
  Playwright dep, no `playwright.config`, no `e2e/` dir.
- **`--frozen-lockfile` blocks adding it.** The `web` CI job installs with
  `pnpm install --frozen-lockfile`; adding `@playwright/test` to `package.json`
  without a **regenerated `pnpm-lock.yaml`** fails install immediately, and the
  lockfile cannot be regenerated in the implementation environment (the same
  constraint that forced "Path A" in M1.22/M1.23).
- **No `e2e` CI job exists.** The current workflow is `guards · api · engine ·
  web · smoke`. The `smoke` job is **API-level** (postgres + uvicorn + httpx,
  `pytest -m smoke`) — it never starts `next` and has no browser, so it can't
  drive the UI.
- **The planned "CSV-upload" browser step has no UI.** Data import is
  **API-only** (`POST /data/*/import-csv`); there is no upload page to click
  through. (The `today/error.tsx` copy even refers to a future upload UI.)

**Decision:** author the Playwright specs + config under `apps/web/e2e/`, but
keep them **dormant** — excluded from vitest / tsc / eslint / `next build` so the
suite stays green — and document the activation path (below). Phase-1 exit
criterion #7 ("Playwright E2E green") is therefore satisfied as **specs authored
+ activation documented**, NOT as a green CI gate. This is called out honestly
rather than faking a green check.

### 2. Calibration is a P1 *scaffold*, not full validation

Plan §19: *"Calibration tests (P3, but scaffolded in P1) — run engine across 12
months of historical fixtures; bin by `confidence`; assert empirical success
rate is monotonic across bins."* We have **no labelled-outcome corpus** yet
(the Outcome Tracker shipped in M1.23; rows accumulate over time; the real suite
is **M3.10**). So M1.25 ships the **machinery + a representative scaffold**, and
harvests the 12 golden `confidence` values to prove integration with real engine
output. No new code under `packages/engine/engine/` → **no engine version bump /
CHANGELOG entry** (the bump guard is scoped to `engine/engine/`; this is a
`tests/`-only addition).

### Calibration scaffold (`test_calibration.py`)

Pure helpers (reused by the M3.10 suite): `bin_index(confidence, n_bins)`,
`binned_success_rates(samples, n_bins)` (empty bins → `None`),
`is_monotonic_nondecreasing(rates)`. Tests: bin edges + clamp; rejects
`n_bins < 1`; a synthetic **calibrated** corpus is monotonic
(`[0.0, 0.0, 0.5, 1.0, 1.0]`); an **anti-calibrated** corpus fails the check
(teeth); empty bins are skipped; and an integration smoke bins the 12 real
golden confidences. Ruleset: ruff `E/F/I/B/UP/N/W` (the file is under `tests/`,
so it is **not** under `mypy --strict engine`, but it is annotated anyway).

### Dormant Playwright E2E

## Activation (out-of-band — regenerates the lockfile)

```bash
pnpm -C apps/web add -D @playwright/test
pnpm -C apps/web exec playwright install --with-deps chromium
BASE_URL=http://localhost:3000 pnpm -C apps/web e2e
```

Then add an `e2e` CI job that boots the full stack and seeds a session:

```yaml
  e2e:
    name: E2E (Playwright)
    runs-on: ubuntu-latest
    services:
      postgres: { image: postgres:16-alpine, ... }     # as in the `smoke` job
    steps:
      - uses: actions/checkout@v6
      - uses: pnpm/action-setup@v6
      - uses: actions/setup-node@v5            # cache: pnpm
      - run: pnpm install --frozen-lockfile     # now includes @playwright/test
      - run: pnpm -C apps/web exec playwright install --with-deps chromium
      - run: <alembic upgrade + start uvicorn (API) + seed chain/positions/iv + a session>
      - run: pnpm -C apps/web build && pnpm -C apps/web start &   # next on :3000
      - run: BASE_URL=http://localhost:3000 E2E_DECISION_ID=<seeded> pnpm -C apps/web e2e
```

## Open questions / risks

1. **E2E is not a CI gate in this environment.** Phase-1 Done bar #7 is met as
   "authored + documented activation", not a green check. Closing it for real
   needs the lockfile regen + the `e2e` job above (a CI-infra task).
2. **No CSV-upload UI.** The browser E2E seeds via the API; a future data-import
   UI milestone would make the literal plan flow browser-driven.
3. **Calibration corpus is synthetic + golden-derived.** Real monotonic-success
   validation is **M3.10**, gated on accumulated `/outcomes` rows.
4. **Polish scope.** Kept deliberately minimal (page titles) to protect the
   green suite; a nav active-state / richer empty states are easy follow-ups.
